🛠️ README DE SOLUCIÓN — PHIXOR18.md + SECURITY

📋 Diagnóstico del fallo

El workflow auto-label-merge-conflicts.yaml falla porque:

1. Permisos insuficientes: el token por defecto no tiene pull-requests: write.
2. Job triage falla en 22s: probablemente la acción no encuentra el PR o no puede etiquetarlo.
3. Attempt #3: reintentos automáticos que también fallan por la misma causa raíz.
4. Branch #PHIXOR18.md: el # en el nombre de la rama rompe algunas acciones de GitHub.

✅ Solución paso a paso

1. Corregir permisos del workflow

En tu archivo .github/workflows/auto-label-merge-conflicts.yaml:

```yaml
name: Auto-label merge conflicts

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: read
  pull-requests: write  # ← ESTO ES LO QUE FALTA

jobs:
  triage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Check for merge conflicts
        uses: eps1lon/actions-label-merge-conflict@v3
        with:
          dirtyLabel: "conflicts"
          repoToken: "${{ secrets.GITHUB_TOKEN }}"
          commentOnDirty: "🚨 Este PR tiene conflictos. Por favor resuélvelos antes de continuar, mi SR GAZOO RACING."
```

2. Renombrar la rama #PHIXOR18.md

GitHub no ama los # en nombres de rama. Sugerencia:

```bash
git branch -m "#PHIXOR18.md" "phixor18-md"
git push origin -u phixor18-md
git push origin --delete "#PHIXOR18.md"  # solo cuando estés seguro
```

```yaml
      - name: Debug context
        run: |
          echo "PR: ${{ github.event.pull_request.number }}"
          echo "Branch: ${{ github.head_ref }}"
          echo "Repo: ${{ github.repository }}"
```

El fallo en el workflow auto-label-merge-conflicts (error en el job triage tras 22s) se debe a dos problemas principales: caracteres reservados (#) en los nombres de las ramas y la falta de permisos explícitos de escritura para GITHUB_TOKEN.

Diagnóstico Técnico

Caracteres especiales en nombres de ramas: Nombres como #PHIXOR18.md o ##FoP-638-#PHIXOR13.md contienen #, el cual es interpretado por el intérprete de comandos y la API de GitHub como un comentario o fragmento URI, rompiendo la resolución de refs.

Permisos de GITHUB_TOKEN restringidos: Las políticas actuales de GitHub Actions ejecutan los workflows en modo lectura por defecto. Para etiquetar PRs o buscar conflictos, el token requiere permisos explícitos de pull-requests: write.

Solución: .github/workflows/auto-label-merge-conflicts.yaml

Reemplaza el contenido de tu archivo workflow con el siguiente bloque configurado con permisos y manejo seguro de tokens:

name: "Auto-label merge conflicts" on: push: pull_request_target: types: [synchronize, opened, reopened, labeled, unlabeled] permissions: contents: read pull-requests: write issues: write jobs: triage: runs-on: ubuntu-latest steps: - name: Label Merge Conflicts uses: eps1lon/actions-label-merge-conflict@v3 with: dirtyLabel: "conflicts" repoToken: "${{ secrets.GITHUB_TOKEN }}" retryAfter: 5 retryMax: 3 

Acciones Recomendadas en Git

Habilitar permisos globales en GitHub: Ve a Settings > Actions > General > Workflow permissions en tu repositorio y asegura que esté seleccionada la opción Read and write permissions.

Con estos cambios, el job triage ejecutará la verificación sin romper la sintaxis del parser ni rebotar por falta de privilegios.
